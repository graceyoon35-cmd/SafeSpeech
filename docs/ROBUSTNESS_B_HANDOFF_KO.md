# 평가 담당자에게 전달하는 파일 묶음

이미 성공한 sweep의 변환 WAV·MP3와 원본/보호 입력을 묶습니다.
실험을 다시 실행하지 않고, 입력·산출물 해시와 WAV 메타데이터부터 확인합니다.

    python scripts/export_robustness_handoff_b.py runs/실험폴더/summary.json

새 runs/handoff_b_* 폴더와 같은 이름의 ZIP을 만듭니다.
입력 파일, 변환 파일, 설정, 조건표, 평가 파일 쌍 목록을 포함하며 모든 경로를
패키지 내부 상대 경로로 바꿉니다. PC나 운영체제가 달라도 전체 폴더를 옮겨 사용할 수 있습니다.
원본 실험 폴더를 수정하지 않고 새 복사본을 만듭니다.

## 전달 항목

- inputs/: 변환 전 원본과 실제 SPEC 보호 WAV
- results/: 조건/회차/역할별 WAV 및 중간 MP3
- experiment.json: 입력 파일과 변환 조건
- artifacts.csv: 파일별 Hz·샘플 수·길이·클리핑·해시
- evaluation_pairs.csv: 같은 조건의 원본/보호 파일 쌍 및 변환 전 입력 위치
- verification.json: 실험 규모, 입력 보존, 재현성 확인, 실행 환경
- package_manifest.json: 전달 파일 SHA-256 목록
- README_KO.md: 압축 해제 및 평가 범위 안내

평가 쌍 목록은 비교 대상 파일을 찾기 위한 자료입니다. 기준 음성을 어떻게 잡을지는
평가 담당자와 합의해야 하며, 이 기능은 STOI/SIM/MCD/WER를 계산하지 않습니다.
동일조건 변환 쌍은 Hz·길이가 같음을 확인합니다. 변환 전 원본을 기준으로 평가하려면
특히 리샘플링에서 명시적 정렬 정책이 필요합니다.

## 확인 범위

원본·보호 음성 한 쌍, 15조건, 2회 반복은 WAV 60개·MP3 12개·평가쌍 30건입니다.
같은 조건의 2회 반복은 재현성 확인이며 독립적인 발화 2개를 의미하지 않습니다.
PASS는 변환·저장·파일 보존·전달 무결성 확인입니다. 보호 효과나 통계적 강건성 결론이 아닙니다.
추가 실험 조건은 탐색용이며 팀 최종 합의·논문 재현 조건이라고 간주하지 않습니다.

압축 해제 후 코드에서 verify_handoff(압축해제폴더)를 호출해 전달 파일의 해시를
검사할 수 있습니다. ZIP 검증 테스트는 경로가 달라진 환경에서도 이 검사가 통과하는지 확인합니다.
원본 패키지 내용은 검사되지만 manifest 자체에 대한 전자서명 기능은 제공하지 않습니다.
