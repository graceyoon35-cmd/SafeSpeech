## 2-1. 언어·모델별 샘플레이트

**"기본값 24000"은 영어(LibriTTS) 경로에서만 맞습니다.** 한국어 MeloTTS 경로는 44100입니다. 두 경로의 음성을 섞어 평가하지 마세요.

| 언어 | 모델·단계 | 샘플레이트 | 근거 | 확인 수준 |
|---|---|---|---|---|
| 영어 | Bert-VITS2 (LibriTTS) 입력·섭동 출력 | **24000 Hz**, 모노 | `bert_vits2/configs/libritts_bert_vits2.json`, `cmu_arctic_bert_vits2.json`의 `sampling_rate`. 원본 168개 모두 24000 Hz·모노·PCM_16 | 설정 파일과 실제 파일 168개 확인 |
| 영어 | Bert-VITS2 범용 `config.json` | 44100 Hz | `bert_vits2/configs/config.json` | LibriTTS 실험에는 쓰지 않음 |
| 영어·한국어 | XTTS-v2 합성 출력 | **24000 Hz** | `melo_kr/attack_xtts.py`가 24000으로 저장 | 코드 확인, 실행 미검증 |
| 한국어 | MeloTTS-Korean 모델, 파인튜닝 학습 데이터 | **44100 Hz**, 모노, PCM_16 | `melo_kr/prepare_finetune.py`의 `MELO_SR = 44100`, `melo_kr/README_KO.md` | 코드·README 확인, 실행 미검증 |
| 한국어 | 녹음 원본 | 정해져 있지 않음 (녹음 장치 값) | README는 "2~10초, 모노 권장"만 명시 | 파일마다 측정해서 목록표에 기록 |
| 한국어 | 섭동(protected) 출력 | 입력과 같음 | README: 섭동은 입력 샘플레이트 그대로 만듦 | README 설명 |
| 공통 | STOI 평가 | 두 음성의 샘플레이트·샘플 수가 같아야 함 | `scripts/run_experiment.py`, 테스트 9개(다른 샘플레이트 거부) | 테스트로 확인 |

- 한국어 경로에서는 한 사람의 음성이 **샘플레이트가 다른 파일 세 종류**로 생길 수 있습니다: 녹음 원본, 보호 음성(입력과 같음), `data/melo_ft/`의 44100 Hz 학습용 복사본(원본은 건드리지 않음).
- XTTS 합성(24000)과 MeloTTS 계열(44100)을 STOI로 비교하려면 샘플레이트가 같아야 합니다. 평가 스크립트에는 **자동 변환이 없고 다르면 거부**하므로, 어느 쪽에 맞출지 팀 합의가 필요합니다.
- 모든 파일의 샘플레이트는 추정하지 말고 파일에서 읽은 값을 `SafeSpeech_data_list.csv`에 적습니다.

## 2-2. 작업별 입출력 형식

각 스크립트의 인자와 코드가 만드는 파일을 소스에서 읽어 정리했습니다.

**읽는 법**

- 확인 수준 **실행**: 팀 기록에서 실제로 돌려 본 것
- 확인 수준 **코드**: 소스를 읽어 정리했을 뿐 실행하지 않은 것
- 확인 수준 **Mock**: 가짜 데이터로만 돌려 본 것
- 경로는 따로 적지 않으면 저장소 루트 기준입니다.

### 영어 경로 (Bert-VITS2, LibriTTS, 24000 Hz)

#### 1) 모델 받기

`python scripts/download_setup_models.py`

- **입력**
  - 없음 (인터넷 필요)
- **출력**
  - 파일 8개를 `checkpoints/base_models/`, `bert/deberta-v3-large/`, `bert_vits2/slm/wavlm-base-plus/`에 저장
  - 화면에 `DOWNLOAD`, `VERIFIED` 표시
  - 이미 있는 파일은 덮어쓰지 않고 해시만 확인
- **확인 수준**: 실행 (Colab)

#### 2) GPU 점검

`python scripts/check_gpu_audio.py`

- **입력**
  - 없음
- **출력**
  - 화면에 JSON (`status: PASS`, torch·GPU·numpy 버전)
  - 파일은 저장하지 않음
- **확인 수준**: 실행 (Colab)

#### 3) 섭동 생성 smoke

`python scripts/smoke_perturbation.py --iterations N`

- **입력**
  - `--iterations`: 반복 횟수 (기본 1)
  - 음성은 직접 지정하지 않음. `libritts_bert_vits2.json`의 학습 목록(`training_files`)에서 영어 행 중 **1초 이상 가장 짧은 1개**를 자동으로 고름
  - GPU 필요
- **출력** (`runs/smoke_<날짜시각 KST>/` 폴더 안)
  - 원본 복사 WAV
  - `input.cleaned` (목록 1줄)
  - `*.bert.pt`
  - `perturbation.pt`
  - `protected.wav` (float WAV, 24000 Hz, 원본 길이)
  - `report.json` (반복 수, ε=8/255, 손실, GPU 메모리)
- **확인 수준**: 실행 (Colab)

#### 4) 평가 점검

`python scripts/smoke_evaluation.py`

- **입력**
  - `--reference`: WAV (기본 `data/LibriTTS/5339/5339_14134_000092_000003.wav`)
  - `--candidate`: 비교할 WAV (선택). 없으면 seed 잡음(std 0.005) 대조군을 씀
  - `--seed`: 기본 42
  - `--output-root`: 기본 `runs`
- **출력** (`runs/evaluation_smoke_*/` 폴더 안)
  - `reference.wav`, `candidate.wav` (float WAV)
  - `report.json` (STOI 등)
- **확인 수준**: 실행 (WSL)

#### 5) Gaussian + STOI

`python scripts/run_experiment.py experiments/gaussian_smoke.json`

- **입력**: 설정 파일 하나 (manifest JSON, 스키마 v1)
  - `audio.original`, `audio.protected`, `audio.synthetic`: 음성 경로. **manifest 파일이 있는 폴더 기준**, 없으면 `null`
  - `evaluation`: `reference_role`, `target_role`, `alignment: strict`
  - `transform`: `gaussian_noise`, `seed`, `std`
- **음성 조건**
  - 모노, 1초 이상, 유한값, 진폭 -1~1, 무음 아님
  - 비교하는 두 음성은 샘플레이트와 샘플 수가 같아야 함
- **출력** (`runs/experiment_*/` 폴더 안)
  - `report.json`: STOI 변환 전·후·변화량, 입력 SHA-256 (실행 전후), 설정, 버전
  - `transformed.wav`: float64 계산값을 보존
- **확인 수준**: 실행 (WSL)

### 한국어 경로 (MeloTTS 44100 Hz + XTTS 24000 Hz)

#### 6) 모델 받기

`python melo_kr/download_models.py --melo --xtts`

- **입력**
  - 없음 (인터넷 필요)
- **출력**
  - `checkpoints/melo_kr/`: `config.json`, `checkpoint.pth`
  - `checkpoints/xtts_v2/`: `config.json`, `model.pth`, `vocab.json` (`speakers_xtts.pth`는 없어도 됨)
- **확인 수준**: 코드

#### 7) 섭동 생성 (한국어)

`python melo_kr/protect_melo.py --input-dir data/korean/clean --out-dir data/korean/protected/SPEC`

- **입력**
  - 다음 중 하나
    - `--input-dir`: 하위 폴더까지 모든 .wav
    - `--inputs`: 파일을 직접 나열
    - `--filelist`: `경로|...` 형식 목록 (첫 칸만 사용)
  - `--out-dir`: 이미 있으면 중단
  - 옵션: `--mode` (`SPEC` 또는 `SafeSpeech`), `--iters` (200), `--epsilon` (8, 255로 나눔)
  - WAV 샘플레이트는 무관 (내부에서 44100으로 변환), 스테레오는 모노로 합침
- **출력**
  - `<out-dir>/<원본 파일명>.wav`: PCM16, **입력과 같은 샘플레이트·길이**
  - `<out-dir>/report.json`: 인자, 모델 샘플레이트, 파일별 손실·SNR·최대 변화량
  - 원본은 읽기만 함
- **확인 수준**: 코드 (무작위 가중치로 경로만 점검됨)

#### 8) 파인튜닝 데이터 준비

`python melo_kr/prepare_finetune.py --audio-dir data/korean/clean --name clean --asr`

- **입력**
  - `--audio-dir`: WAV 폴더
  - `--name`: 세트 이름 (이미 있으면 중단)
  - 대본 (둘 중 하나)
    - `--transcripts`: CSV (머리글 `file,text`)
    - `--asr`: Whisper가 한국어로 자동 생성
- **출력** (`data/melo_ft/<name>/` 폴더 안)
  - `wavs/*.wav`: **44100 Hz, 모노, PCM16** (원본은 그대로)
  - `metadata.list`: `절대경로|화자|KR|문장`
  - `transcripts.csv`: `file,text`
  - 문장 속 `|`는 공백으로 바뀌고, 대본이 빈 파일은 건너뜀
- **확인 수준**: 코드

#### 9) MeloTTS 학습

`melo_kr/README_KO.md` 5절 절차 (MeloTTS 환경)

- **입력**
  - `metadata.list` → `preprocess_text.py`가 `config.json`을 만든 뒤 `train.py` 실행
- **출력**
  - `third_party/MeloTTS/melo/logs/melo_ft_<이름>/G_<step>.pth`
- **확인 수준**: README만 (실행하지 않음)

#### 10) MeloTTS 합성

`python melo_kr/synth_melo.py --ckpt <G_*.pth> --config <config.json> --label SPEC`

- **입력**
  - `--ckpt`: 학습된 체크포인트 (`G_*.pth`)
  - `--config`: 위 `config.json`
  - `--label`: 조건 이름
  - `--texts`: 기본 `melo_kr/test_sentences_ko.txt` (한 줄에 한 문장, 10문장)
  - `--speaker`: 기본 `target`
  - `--seed`: 기본 1234
- **출력** (`runs/melo_attack/<label>/` 폴더 안)
  - `000.wav`, `001.wav`, …
  - `metadata.csv`: 열 `reference, sentence_id, text, output`
  - 샘플레이트는 코드에 지정이 없고 모델 설정을 따름
- **확인 수준**: 코드

#### 11) XTTS 제로샷

`python melo_kr/attack_xtts.py --refs data/korean/clean --label clean`

- **입력**
  - `--refs`: 참조 WAV 또는 폴더
  - `--label`: 조건 이름 (같은 폴더가 이미 있으면 중단)
  - `--texts`: 기본 `melo_kr/test_sentences_ko.txt`
  - `--language`: 기본 `ko`
  - `--model-dir`: 기본 `checkpoints/xtts_v2`
  - `--seed`: 기본 1234
- **출력** (`runs/xtts_attack/<label>/` 폴더 안)
  - `<참조 파일명>/<문장번호>.wav`: **24000 Hz**, PCM16
  - `metadata.csv`: 위 10)과 같은 4열
- **확인 수준**: 코드

#### 12) 채점 (SIM, ASR, CER)

`python melo_kr/evaluate_kr.py --meta <metadata.csv> ... --speaker-refs data/korean/clean --out runs/eval_xtts`

- **입력**
  - `--meta`: 조건별 `metadata.csv`. **조건 이름은 그 파일이 들어 있는 폴더 이름**
  - `--speaker-refs`: 화자의 원본 WAV 폴더 (최대 5개와 비교)
  - `--out`: 결과 폴더 (이미 있으면 중단)
- **출력** (`--out` 폴더 안)
  - `per_file.csv`: 파일별 SIM, 공격 성공 여부, 전사문, CER
  - `summary.csv`: 조건별 SIM, ASR(%), CER(%)
  - `summary.json`
  - SIM 기준은 0.25, CER은 Whisper 다국어 `medium`으로 계산
- **확인 수준**: 코드

### XTTS 영어·한국어 쌍 (`feature/xtts-v2`)

#### 13) 원본·보호 음성으로 쌍 합성

`python scripts/run_xtts_pair.py experiments/xtts_pair_pending.json` (단일 합성은 `scripts/xtts_inference.py`)

- **입력**
  - 참조 WAV: `runs/xtts_inputs/clean.wav`, `runs/xtts_inputs/protected.wav` (**같은 길이·샘플레이트의 별도 파일**)
  - 문장, 언어 (소문자 `ko` 또는 `en`), seed
  - 모델: `checkpoints/xtts-v2` (`config.json`, `model.pth`, `vocab.json`)
  - 동의·약관 확인 옵션: `--consent-confirmed --cpml-accepted`
- **출력**
  - 단일 합성: `runs/xtts_single/ko.wav`, `en.wav`
  - 쌍 합성 (`runs/xtts_pair_*/` 폴더 안): `0_ko_clean.wav`, `0_ko_protected.wav`, `1_en_clean.wav`, `1_en_protected.wav`, `report.json`
  - 출력은 24000 Hz
- **확인 수준**: Mock만 실행 (실제 합성은 하지 않음)

확인 수준: 무작위 가중치로 코드 경로만 검증. 환경 3개가 필요하며, 전체 절차는 `melo_kr/README_KO.md`를 따릅니다.

`third_party/MeloTTS`는 저장소에 들어 있지 않습니다(`feature/melo-kr`의 `.gitignore`가 `/third_party/`를 제외). 저장소 루트에서 직접 내려받은 뒤에 설치합니다. 출처는 `melo_kr/README_KO.md`이고, 아직 실행해 보지 않았습니다.

- XTTS 패키지: `coqui-tts[ko]`(버전 미고정)와 `coqui-tts==0.28.0`
- `third_party/MeloTTS`의 커밋과 평가 패키지 버전이 고정되어 있지 않음
