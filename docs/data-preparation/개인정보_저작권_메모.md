## 2. 팀이 정할 것

### 2.1 XTTS-v2를 써도 되는가

CPML은 대가를 받지 않는 연구, 실험, 테스트를 비상업 용도로 인정합니다. 수익 활동과 정부 지원금으로 직접 운영되는 프로젝트는 제외합니다.

- 먼저 확인할 것: 이 프로젝트에 지원금, 연구비, 상금이 걸려 있는지
- 걸려 있으면 XTTS는 쓰지 않는 것으로 합니다.
- 어느 경우든 앱이나 서비스에는 넣지 않고, XTTS 합성 음성을 넘길 때는 약관 URL을 함께 보냅니다.

### 2.2 한국어 녹음은 누구 목소리로 하나

목소리는 누구인지 알아볼 수 있는 정보라서 개인정보로 다룹니다. 이 프로젝트는 그 목소리를 복제하는 실험이라 일반 녹음보다 위험이 큽니다.

동의서에 넣을 항목 (자세한 내용은 대응시트의 "동의서 항목")
1. 목적: 음성 보호 기술 평가
2. 복제 합성: 보호 전후 음성으로 모델을 학습시켜 본인 목소리를 흉내 내는 음성을 만든다는 사실
3. 학습 범위: 파인튜닝 학습까지 쓴다는 사실 (입력 JSON의 `permission_scope=spec_and_finetuning`)
4. 처리 장소: 개인 PC에서만 처리하는지, Colab 같은 외부 서비스를 쓰는지
5. 접근자와 공개 범위: 누가 접근하는지, 발표에서 틀어도 되는지
6. 보관과 삭제: 언제 지우는지
7. 거부와 철회: 동의하지 않아도 불이익이 없고, 언제든 철회할 수 있다는 점
8. 화자 유사도 계산: 평가에서 화자 정보를 쓴다는 사실

관리 규칙
- 파일 이름과 목록에는 실명 대신 `s001` 같은 가명을 씁니다.
- 실명과 가명의 대응표, 동의서는 저장소와 공유 폴더 밖에 따로 보관합니다.
- 학습된 체크포인트도 그 사람의 목소리를 담고 있으므로 원본 음성과 같이 삭제합니다.
- 공인이나 유명인의 음성, 인터넷에서 받은 음성은 쓰지 않습니다.
- 발표에서 음성을 틀려면 녹음한 사람에게 따로 동의를 받습니다.

## 3. 저장소에서 발견한 위험

| 위험 | 내용 | 제안 |
|---|---|---|
| 실제 목소리 유출 | `/data/korean/` 제외 규칙이 `feature/melo-kr`에만 있음. `master`, `feature/data-preparation`, `feature/bert-vits2`에는 `.gitignore`가 없음 (11/3 확인) | 규칙을 공통 브랜치에 넣기 전에는 이 브랜치에서 `git add .` 금지 |
| 출처 기록 누락 | `DATA_ATTRIBUTION.md`가 문서에서 언급되지만 저장소 어느 브랜치 루트에도 없음 | 저장소에 출처 문서를 하나 추가 |
| 개인 경로 노출 | 공개 문서 `QUICKSTART_KO.md` 등에 팀원 이름이 든 경로(`/mnt/c/Users/...`)가 있음 | 해당 팀원에게 알리고 `<저장소 경로>`로 교체 |
| 전달 파일의 절대 경로 | 한국어 SPEC 전달 목록과 검증 JSON에 로컬 절대 경로가 들어감 (사용자 이름 포함 가능) | 실제 녹음의 목록과 허가 기록은 `runs/` 비공개 폴더에만 두고 Git에 올리지 않음 |
