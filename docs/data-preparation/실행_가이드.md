## 2. 공통 규칙

저장소 받기 (옛 이름 `feature/cpu-experiment-pipeline`은 이제 없습니다)

```bash
git clone --branch feature/metrics https://github.com/graceyoon35-cmd/SafeSpeech.git
cd SafeSpeech
```

- 명령은 저장소 루트에서 실행합니다.
- 문서의 `/mnt/c/Users/...` 경로는 작성자 PC 기준입니다. 본인 경로로 바꾸세요.
- 환경은 섞지 않습니다. 원본 `requirements.txt`는 설치하지 않습니다.
- 올리지 않는 것: 모델 가중치(`checkpoints/`), 실행 결과(`runs/`), 실제 목소리, 합성 음성, 동의서.
- `master`, `feature/bert-vits2`, `feature/data-preparation`에는 `.gitignore`가 없습니다 (11/3 확인). 이 브랜치에서는 `git add .`를 쓰지 말고 파일을 지정해서 올리세요.

## 3. Windows WSL, CPU 평가 (feature/metrics)

상태: 확인함 (11/10, 새 clone, 커밋 27ae06d)

Ubuntu 터미널에서 실행합니다. PowerShell이 아닙니다.

```bash
sudo apt-get update
sudo apt-get install -y python3-venv python3-pip libsndfile1
python3 -m venv "$HOME/.venvs/safespeech-cpu"
source "$HOME/.venvs/safespeech-cpu/bin/activate"
python -m pip install -r requirements-evaluation-smoke.txt
python -m pip check
python scripts/smoke_evaluation.py
python scripts/run_experiment.py experiments/gaussian_smoke.json
python -m unittest discover -s scripts -p 'test_*.py' -v
```

확인한 결과
- 설치: numpy 1.26.4, scipy 1.13.1, soundfile 0.12.1, pystoi 0.4.1
- `pip check`: 충돌 없음
- `smoke_evaluation.py`: 통과, 잡음 대조군 STOI 0.9703
- `run_experiment.py`: 통과, STOI 1.0에서 0.9703으로 변화
- 테스트 9개 통과

결과는 `runs/` 아래 새 폴더에 저장됩니다.

## 5. 한국어 MeloTTS SPEC 1회, 10회 (feature/spec-perturbation)

상태: 설치와 테스트는 확인함, 실제 SPEC 실행은 미실행 (모델 파일 없음)

확인한 것 (11/10, 커밋 412c358, WSL CPU)
- `requirements-spec-stoi.txt` 설치 성공, `pip check` 충돌 없음
- 테스트 35개 통과
- 입력 템플릿을 그대로 검증하면 "대본 검수 선언 필요"라며 거부됨 (의도된 동작)

```bash
pip install -r requirements-spec-stoi.txt
python -m unittest discover -s scripts -p 'test_*.py'
python -B scripts/run_korean_melo_spec.py --manifest <입력 JSON> --validate-only
```

실제 실행에는 `--assets` 폴더가 필요합니다. 공식 MeloTTS 소스, `model/`, `effective_loss_config_verified.json`이 든 폴더이고 Git에 없습니다. 섭동 담당에게 받아야 합니다.

```bash
python -B scripts/run_korean_melo_spec.py \
  --manifest <입력 JSON> --assets <assets 폴더> \
  --seed 52 --epsilon 8 --iterations 1 10 --device cpu
```

입력 JSON에 채울 값 (양식: `docs/templates/korean_spec_input.template.json`)

| 필드 | 값 |
|---|---|
| `utterance_id` | 발화마다 고유한 ID (예: ko_s001_u001) |
| `speaker_id` | 실명 대신 가명 (예: s001) |
| `input_kind` | `human_recording`, `model_synthesized`, `mock` 중 실제 출처 |
| `text` | 한국어 대본 |
| `transcript_verified` | 사람이 듣고 대본을 대조한 뒤에만 true |
| `research_use_permitted` | 사용 허가를 받은 뒤에만 true |
| `permission_scope` | 실제 녹음은 `spec_and_finetuning` |
| `permission_reference` | 동의서 번호 |
| `split` | `train`, `validation`, `test` 중 하나 |
| `original_path`, `original_sha256`, `sample_rate` | 파일에서 읽은 값 |

- 합성이나 Mock 입력은 `--allow-nonhuman`이 있어야 실행되고, 결과는 파인튜닝에 넘길 수 없습니다.
- 실제 녹음, 허가 기록, 입력 JSON은 GitHub에 올리지 않습니다.
- STOI는 소리가 얼마나 알아들을 만한지를 보는 지표입니다. 복제를 막았다는 증거가 아닙니다.

## 6. NVIDIA GPU가 있는 PC (영어 섭동 생성)

상태: 문서 기준 (RTX 5060 Ti, Colab T4 실행 기록). 제 PC는 GPU가 없어 실행하지 못했습니다.

## 7. 한국어 보호와 XTTS (feature/melo-kr, feature/xtts-v2)

상태: 미검증 (무작위 가중치로 코드 경로만 확인된 상태). 전체 절차는 `melo_kr/README_KO.md`를 따릅니다.

환경이 3개 필요합니다.

| 환경 | 위치 | 용도 |
|---|---|---|
| 기본 | `~/.venvs/safespeech` | 가중치 다운로드, 섭동 생성, 채점 |
| XTTS | `~/.venvs/xtts` | 제로샷 공격 |
| MeloTTS | `~/.venvs/melo` | 파인튜닝 공격 (Python 3.10) |

문서끼리 다른 점 (팀이 정해야 함)
- XTTS 환경 위치: `~/.venvs/xtts`와 `.venv-xtts`
- XTTS 모델 폴더: `checkpoints/xtts_v2`와 `checkpoints/xtts-v2` (이름이 달라서 한쪽에서 받은 모델을 다른 쪽이 못 찾음)
- XTTS 패키지: `coqui-tts[ko]`(버전 없음)와 `coqui-tts==0.28.0`
- `third_party/MeloTTS`는 저장소에 없고, 받은 시점의 커밋이 고정되어 있지 않음

## 9. 자주 나는 오류

| 증상 | 원인 | 대처 |
|---|---|---|
| `requirements-evaluation-smoke.txt`를 찾을 수 없음 | `feature/spec-perturbation`에는 이 파일이 없음 | 그 브랜치에서는 `requirements-spec-stoi.txt` 사용 (내용 같음) |
| `scripts/smoke_evaluation.py`, `run_experiment.py`가 없음 | 두 파일은 `feature/metrics`에만 있음 | `feature/metrics`로 clone |
| `ModuleNotFoundError: numpy` | 가상환경에 설치 전에 테스트 실행 | 가상환경 활성화 후 requirements 설치 |
| WSL에서 `git clone`이 `unable to access`로 실패 | 일시적인 네트워크 오류 | 잠시 뒤 다시 시도 (11/10에 1회 발생, 재시도로 해결) |
| clone 명령이 브랜치를 찾지 못함 | 옛 이름 `feature/cpu-experiment-pipeline` 사용 | `feature/metrics`로 교체 |
| Python 3.13에서 설치 실패 | 환경이 3.10 기준 | Python 3.10 가상환경 사용 |
| NumPy, librosa 버전 충돌 | 환경을 섞어서 설치 | 작업별로 환경을 나눔 |
| `run_korean_melo_spec.py --validate-only`가 거부 | 템플릿 기본값은 허가와 대본 검수가 false | 의도된 동작. 실제로 확인한 뒤에만 true로 바꿈 |
| 같은 해시가 다른 split에 있다고 거부 | 같은 음성이 train과 test에 중복 | 한 split에만 둠 |
| 합성 입력이 `--allow-nonhuman` 없다고 중단 | 합성과 Mock은 명시 옵션 필요 | 옵션을 붙이면 실행되지만 파인튜닝에는 못 넘김 |
| STOI 길이 오류 | strict 모드는 샘플레이트와 샘플 수가 같아야 함 | 자동 자르기는 없음. 정렬 방식은 팀이 정해야 함 |
