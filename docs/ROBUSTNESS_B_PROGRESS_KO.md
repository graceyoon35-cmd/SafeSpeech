## 개발 위치

- Windows의 VS Code, Python 3.10.22 CPU 환경에서 개발합니다.
- GPU가 필요한 SPEC 생성·모델 작업은 기존 Colab을 사용합니다.
- 작업 브랜치는 feature/robustness 하나만 사용합니다.
- 다른 팀 브랜치는 읽기·비교만 하며 수정·커밋·Push하지 않습니다.

## 완료한 확인

1. 기존 Colab에서 생성한 실제 SPEC 10회 보호 음성과 원본 음성 한 쌍을 복사했습니다.
2. 같은 조건을 원본·보호에 적용하는 Gaussian·MP3·리샘플링 변환이 통과했습니다.
3. 15조건 × 원본/보호 × 동일조건 2회 실험에서 WAV 60개·MP3 12개가 생성됐습니다.
4. 동일조건의 출력 파일 해시가 일치하고 입력 음성 해시는 유지됐습니다.
5. 조건·역할·회차·Hz·길이·파일 경로·해시를 CSV/JSON으로 저장했습니다.
6. 전달용 ZIP에 변환 전 입력 음성 2개, 변환 결과, 상대 경로 목록과 체크섬을 묶었습니다.
7. 전체 자동 테스트 26개 통과 후 전달 기능의 최종 변경에 대해 해당 테스트 4개를 재확인했습니다.

실험 조건은 Gaussian std 0.001/0.005/0.01 × seed 42/43/44,
MP3 32/64/128 kbps, 리샘플링 8000/12000/16000 Hz입니다.
같은 조건의 두 번 실행은 재현성 검사이며 독립 발화 표본 수를 늘린 것이 아닙니다.
추가 테스트의 보호 입력은 합성 fixture이고, 실제 실행에 사용한 SPEC 보호 입력과 구분됩니다.

## 전달 상태와 남은 작업

- 사용자는 1학년 B 평가 담당자에게 최초 3종 변환 결과를 전달했습니다.
- 새 15조건 결과 묶음은 준비했으며 별도로 전달할 수 있습니다.
- 평가 담당자의 실행 결과·회신은 아직 확인하지 않았습니다.
- STOI/SIM/MCD/WER 점수와 모델 합성 결과는 이 단계에서 산출하지 않았습니다.
- 기준 음성 및 리샘플링 정렬 정책을 평가 담당자와 확인해야 합니다.
- 여러 발화의 실제 원본/SPEC 쌍을 확보한 뒤 발화 ID별 실험을 확대합니다.
- 공개 체크포인트의 화자 임베딩 누락 등 기존 SPEC 생성 제약은 그대로 남습니다.
